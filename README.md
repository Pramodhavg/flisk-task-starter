# Flisk task starter: running with Flisk

A 5-service voting app (Python vote page, Node.js results page, .NET worker, Redis, Postgres), run locally with Flisk instead of Docker Compose.

I did this on **Windows 11 with WSL2 (Ubuntu)**, Docker Desktop 29.8.2, Flisk CLI 1.4.37, Tilt 0.37.8, Node 24.

## How to start it

### macOS / Linux

    npx @flisk-sh/flisk import .
    npx @flisk-sh/flisk up

### Windows

Container services need Ubuntu on WSL2. Native Windows only runs services that declare a command as local processes.

1. Install Ubuntu on WSL2: `wsl --install -d Ubuntu`
2. Docker Desktop → Settings → Resources → WSL integration → turn Ubuntu on
3. Inside Ubuntu, install Node 22.12+ (I used nvm) and Tilt (Linux installer, not the Windows one)
4. Clone into the Ubuntu home folder (`~/`), not `/mnt/c` or `/mnt/d`, so file watching works and builds stay fast
5. Run:

        npx @flisk-sh/flisk import .
        npx @flisk-sh/flisk up

Then run `npx @flisk-sh/flisk networks` for the URLs. On my machine port 80 was taken, so Flisk picked 8082:

- Vote: http://api.flisk-task-starter.localhost:8082/api/vote
- Results: http://api.flisk-task-starter.localhost:8082/api/result

I voted on the vote page and saw it on the results page, so the whole chain (vote → Redis → worker → Postgres → result) works.

**Warm start on WSL2: 24 seconds** until "Flisk is up" with 14/14 resources ready, measured on this app.

## What was hard

- **Windows needs WSL2, and I only found out at `flisk up`.** The site says Docker is optional and lists Windows, and `import` ran fine in PowerShell. Then `up` stopped with "Landscape startup needs Ubuntu on WSL2." I had to install Node and Tilt a second time inside Ubuntu, and move the project out of `D:\` into the Ubuntu home folder. An earlier warning, for example during `import`, would have saved most of that time.
- **Generated files were not gitignored.** Flisk said it added its generated files to `.gitignore`, but `git status --untracked-files=all` still showed hundreds of files under `.flisk/.flisk-out/` and `services/*/.autogenerated/`, including `.env.backend.autogenerated` files. A plain `git add -A` would have committed them. I added both folders to `.gitignore` by hand.
- **`import` and `up` disagree about `seed`.** `import` turned the `seed` profile into a normal sixth service, but `up` then skipped it ("Not starting seed (profile seed)"). The task page also says profiles are not enforced. Three different answers to the same question.
- **Env values: "names only", then "copied 1 value".** The import plan listed `POSTGRES_PASSWORD, POSTGRES_USER (names only)`, but the last line said it copied 1 environment value into `.env`.
- **Health checks are guessed.** Vote and result got `/` as an assumed health path, and Traefik only routes while it answers 2xx/3xx. It worked here, but an app whose `/` redirects to a login page or returns an error would look "down".
- **A Node warning on Windows only.** On Windows, Node 26 printed `DEP0190` (child process with `shell: true`) on every command. It did not appear inside WSL.
- **The task page and v1.4.37 differ.** The page shows 5 services and skipped `volumes`/`networks` keys. v1.4.37 found 6 services and no longer warns about volumes or networks. Good progress, but the docs lag behind the tool.

What worked well: the dry run is honest about what it can't translate, the port 80 → 8082 fallback was automatic and explained how to force 80, and after the setup work it started in 24 seconds.

I ran every command myself on my own machine and used an AI assistant as a guide for setup steps and for checking my notes.
